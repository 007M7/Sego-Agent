# Changelog

All notable changes to the Sego Agent project will be documented in this file.

## [Unreleased]

### Added
- **DeepSeek V4.1 Flash routing alias**: `deepseek-v4.1-flash` is accepted as a Sego model alias and normalized to the provider API name `deepseek-flash`; the route is covered by unit/integration tests and a live API request returned `OK`.
- **`api` now exposes the OpenAI base-URL accessor, closing the endpoint gap (PROV-M03)**: `read_openai_base_url()` returns the endpoint the OpenAI-compatible client will use, taken from the same config that client is built from. `resolved_endpoint` therefore has a real value for every provider Sego can route to, instead of being omitted with a named evidence gap. The `identity_evidence_gap` mechanism is deliberately kept — a future provider arriving without an accessor must still be *named* as a gap rather than silently omitted — and a unit test pins that all four routable providers resolve an endpoint. Note the ordering this completes: the gap was exposed first (identity fields, same unreleased block), and eliminated after.
- **Invocation identity now reports evidence strength and the endpoint actually used (`identity_evidence`, `resolved_endpoint`, `identity_evidence_gap`)**: `identity_evidence` currently has the single value `self_reported_resolution` — Sego resolved the route itself and confirmed it against the wire, which is explicitly **not** a provider-side attestation; a future `provider_attested` value is deliberately not declared while Sego cannot produce it, so a consumer cannot misread an absent capability as present. `resolved_endpoint` reports the endpoint taken from the same base-URL accessor the model client uses. When a provider has no accessor (OpenAI, PROV-M03) the value is omitted **and** `identity_evidence_gap` names that gap (`no_endpoint_accessor_for_provider`), rather than substituting a second derivation that could silently differ from the endpoint really used. Verified end-to-end against a mock endpoint: both the response and the persisted artifact reported the endpoint the run actually succeeded against, and both passed the published schemas; the gap path is pinned by a unit test that persists an artifact with no endpoint and asserts the named gap.
- **Caller-minted invocation identity (`context.invocation_id`) on the governed path**: an execution can now be bound to the artifact it produced without pretending that Sego's own `review_id`, `diff_hash` or an index row is an invocation id. The caller supplies an opaque string (for EgoPulse: the verification/checker execution id); Sego never parses it, never derives execution idempotency from it, echoes it in the response and persists it on the artifact. Optional and additive, so requests without it keep current behaviour (response field `null`, artifact field absent). The schema declares `maxLength: 128` and the runtime enforces the same 1..=128 bound, so a request cannot be accepted while being invalid against the contract; a unit test pins that boundary.
- **Sidecar reports the resolved provider and model (`resolved_provider` / `resolved_model`)**: the governed plugin path already resolved the route strictly but discarded it, so a caller had no way to bind its own execution identity to the provider and model an invocation used. Both are now recorded in the success envelope (and declared in the request/response schema, with null companions in the error envelope). The values are **derived from the model name** by the same function the model client uses, never echoed from the request, and the schema description states plainly that this is Sego's routing decision rather than a provider-side attestation.
- **Routing is now validated before the empty-diff shortcut**: strict resolution moved ahead of the `no_diff` return, so an unrecognised provider or model fails with `unknown_provider` / `unknown_model` even when the selected scope has nothing to review. Previously such a request returned a misleading `no_diff` success. Verified end-to-end: with no diff, `provider=deepseek, model=deepseek-chat` returns `no_diff` with `resolved_provider`/`resolved_model` set, while `provider=bogus` now returns `unknown_provider`.
- **The governed sidecar path now records the invocation route in the persisted artifact**: `ReviewArtifact` gained optional `resolved_provider` / `resolved_model`, serialized only when present so artifacts written by other paths keep their existing shape. `runtime` gained an additive `persist_review_artifact_with_identity` and a `ReviewInvocationIdentity` carrier; the existing `persist_review_artifact` keeps its signature and delegates with an empty identity, so no existing caller or test changed behaviour, and a regression test now asserts that artifacts written that way omit both fields (`invocation_identity_is_recorded_only_when_supplied`). Verified end-to-end: a sidecar run writes `"resolved_provider":"anthropic"` / `"resolved_model":"claude-sonnet-4-6"` into `.sego/reviews/*.json`, and the artifact still validates against the published schema.
- **Mitigation awareness in review prompt**: the code review prompt now instructs the model to check for existing mitigations (parameterized queries, allowlists, HMAC/JWT signature verification, sandboxed eval, `shell=False` argument-list form) before reporting a vulnerability pattern. If a mitigation is present and correctly implemented, the finding is downgraded to info; if incomplete or bypassable, it is reported with the specific bypass explained. Identified by an internal 40-diff calibration evaluation (security recall 10/10; false-positive traps revealed over-reporting on mitigated code such as CSRF-exempt webhooks with HMAC verification and allowlist-validated redirects). (#76)

### Changed
- **`parse_status: "no_diff"` is emitted again — the coordinated hold is lifted**: the hold introduced on 2026-09-12 is removed in the same window as the consumer-side change, whose mapper now accepts the value and maps it to Unverified + Missing coverage rather than to a pass. An empty selected scope returns `status: "ok"` with `parse_status: "no_diff"` and **no artifact**, while a scope containing changes returns the normal success envelope — both verified end-to-end and against the published schema. The meaning is unchanged: "no work to review" — not a checker failure, and emphatically not a pass.
- **`parse_status: "no_diff"` is withheld until the consumer's mapper accepts it (coordinated rollout)**: the value stays part of the chosen contract, but the current producer no longer emits it. An empty selected scope now fails closed with error code `review_failed` and an actionable message, instead of returning a success envelope carrying a value the consuming mapper rejects as inconsistent. Re-enabling is a one-line change, to be made in the same window as the consumer-side update. Verified end-to-end: an empty staged scope returns `review_failed` with `parse_status` null. The message states explicitly that this is **not** a checker failure but "no work to review", because the consuming side classifies checker failures from its own process supervision rather than from this code; the two must not be conflated.
- **Public schemas now carry an explicit contract identity and revision**: `schema/*.json` gained `x-contract-id`, `x-contract-revision` and `x-contract-ratified` markers so a consumer can pin and diff the contract source, and the sidecar envelope schema's self-description ("placeholder … refined during PoC") was replaced by its ratified status. This is the precondition the consuming side attached to ratifying the schema alignments: a contract change must land on the contract source, not only in the implementation. Revisions were not tracked before this date, so every schema starts at revision 1. The scope sentence is fixed by the consuming side and is used **verbatim** in all three schemas: `RATIFIED (cross-window technical ratification only). NOT Founder or user acceptance. NOT product-release approval.`
- **README rewritten** to a narrative six-section structure (problem → reproducible usage → how to read results → capability boundaries → EgoPulse relationship → development), aligned with the current product positioning ("engineering trust layer for verifying AI claims"). Removes "independent review" wording (review is model-driven constrained review + deterministic evidence gate), corrects the 91.5% statistic to the faithful source phrasing, documents the read-only default permission, and adds an available/experimental/planned capability matrix. Now bilingual: English default (`README.md`) + 简体中文 (`README.zh-CN.md`) with a cross-linked language switcher and English-language architecture/pipeline figures (`assets/figures/`, TikZ sources included).

- **Strict provider/model routing on the governed sidecar path**: `options.provider` is now accepted, and the sidecar no longer resolves its route through `detect_provider_kind`'s environment-variable priority. An unrecognised provider name fails with `unknown_provider`; a provider supplied without an explicit model fails with `provider_requires_model`; a model whose provider family cannot be determined from its name fails with `unknown_model` instead of falling through to env-var priority; and a model that contradicts the requested provider fails with `provider_model_conflict`. Requiring a determinable family is deliberate: `LiveCli::new` re-derives the provider from the same model name, so the accepted route is the route that runs, rather than an assertion about it. Consequence to note: OpenAI-family model names with no prefix branch (for example `gpt-4o`) were rejected by the sidecar until that gap was closed later in this same unreleased block (see the OpenAI-family entry under Fixed). `api` now re-exports `metadata_for_model` / `ProviderMetadata`, which previously existed but were unreachable from other crates.

- **Sidecar enforces the envelope version (protocol boundary)**: `schema_version` was parsed and then never checked, so a request declaring `schema_version: 2` was silently processed as v1. The sidecar now fails closed with `unsupported_schema_version` when the declared version differs from the implemented one (`SIDECAR_SCHEMA_VERSION = 1`).

- **Sidecar rejects options and context fields it does not read (contract narrowing)**: `options.include_safety_lock` was documented in the request schema but had no field in the Rust struct and no reference anywhere in the code, so passing it looked like configuration and did nothing; `context.user_intent` was declared but never read. Both are removed, `options` / `context` / the request itself now set `additionalProperties: false` in the schema and `#[serde(deny_unknown_fields)]` in the implementation, so any unread key fails the request instead of being silently ignored. If intent context is wanted in the review prompt later, that is a new feature and a new contract change, not a field to re-add silently.

### Fixed
- **The intermittent `prompt.rs` test failure is fixed (a flaky test is a false failure, not a real one)**: `load_system_prompt_reads_claude_files_and_config` intermittently panicked at `runtime/src/prompt.rs:704` during cleanup. Cause: `temp_dir()` derived its path from a nanosecond timestamp alone, and the system clock is coarse enough on some platforms that two tests received the *same* path — so they shared one temp root and one test's `remove_dir_all` deleted the directory another was still using. The path now includes a process-wide monotonic counter, and cleanup no longer panics on failure (`let _ = ...`) so cleanup itself can never manufacture a failure. Verified with **8 consecutive** `cargo test -p runtime` runs: `513 passed; 0 failed; 1 ignored` every time (before the fix the failure appeared roughly once every three runs).
- **A detected artifact-id conflict now fails loudly instead of overwriting an existing artifact**: the artifact id is `review-<epoch-second>-<diff-prefix>`, so two reviews of the same diff finishing in the same second computed the same id — and therefore the same path — and the second silently replaced the first. Measured before the fix: 6 sequential runs left **4 artifacts for 6 index rows**, and 4 concurrent runs left **1 artifact for 4 index rows** (all four rows carrying the same id). Artifact files are now created with `create_new`, so an existing id is refused **atomically** rather than after a check that a concurrent writer could win. The failure carries a readable code (`artifact_id_conflict` on the governed sidecar path) and a named reason including the conflicting id, workspace, scope and `diff_hash`; there is deliberately **no retry with a fresh id**, because that would turn a detected conflict into a silent identity change. A unit test pins the invariant that an existing artifact id can never be written twice and that the earlier artifact survives intact.
- **`finding_status` schema now lists all six statuses**: `ReviewFindingStatus` serializes six values (`report.rs:673-693`) but `schema/review-index-entry.schema.json` listed only four, omitting `accepted_risk` and `false_positive` — so a `status.jsonl` entry carrying either was invalid against the published schema, and those are precisely the two statuses that require an explanatory note. An audit of every enum in all three public schemas against its Rust counterpart found this as the last remaining mismatch. Note for consumers: that file's root `$ref` targets `review_index_entry`, so `status.jsonl` entries validate through `#/$defs/finding_status_entry`.
- **`evidence_coverage` is now declared in the review-artifact schema**: current builds emit a per-file coverage object (`ReviewEvidenceCoverage`, `report.rs:61-71`) on every artifact, but `schema/review-artifact.schema.json` never declared it, so the published contract omitted the very field a consumer needs to judge whether an empty `findings` list means anything. The field is now declared (optional, so older artifacts still validate) with its full shape: `scope_kind`, `file_tree_count`, `observed_files[]` (`path`, `listed`, `content_status`, `captured_line_count`), and the five capture counters (`captured_file_count`, `truncated_file_count`, `not_captured_file_count`, `skipped_large_file_count`, `unreadable_file_count`). `content_status` is constrained to the five values `ReviewContentStatus` serializes. Verified that artifacts with, without, and with a null coverage object all validate, while an unknown `content_status` and a missing `listed` are rejected.
- **`evidence_status` schema and contract table now list all seven values**: `EvidenceStatus` serializes seven variants (`report.rs:17-32`), but `schema/review-artifact.schema.json` and `docs/REVIEW_ARTIFACT_CONTRACT.md` listed only five, omitting `content_not_captured` and `content_truncated`. An artifact carrying either value therefore **failed the published schema** even though the implementation already emitted it — the same class of defect as the sidecar envelope. Both are corrected; the enum change only widens what validates, so nothing that passed before becomes invalid.
- **OpenAI-family model names now resolve to a provider (routing gap)**: `metadata_for_model` had branches for `claude*`, `grok*` and `deepseek*` only, so `gpt-*` / `o1*` / `o3*` / `o4*` / `chatgpt-*` returned `None` and fell through to `detect_provider_kind`'s environment-variable priority — OpenAI was nominally supported but not deterministically routable. A narrow `is_openai_family` branch now resolves them to `ProviderKind::OpenAi` with `OPENAI_API_KEY` / `OPENAI_BASE_URL`. Names that match no family still return `None`, which the governed sidecar path reports as `unknown_model` rather than guessing.
- **Sidecar input binding for `context.diff_hash` is now enforced (D-2)**: the field was parsed and then silently ignored, so a caller asserting a specific diff received a review of whatever the selected scope happened to contain — a false sense of binding. The sidecar now compares the asserted value before any model call or persistence, against the same hash the persisted artifact carries (`review_diff_hash`, `report.rs:741`), and fails with a specific machine-readable code: `{"status":"error","error":{"code":"diff_hash_mismatch", ...}}` at exit code 1. Previously every runtime failure collapsed into `review_failed`; the pipeline now preserves a specific code for this case.

### Documented
- **Contributor guidance now names the traps that already exist in this tree**: `AGENTS.md` records four things that have each misled a reader or a change at least once — the two CLI files that are not compiled (`args.rs` / `app.rs`), the artifact-id collision that now fails with `artifact_id_conflict` instead of overwriting, the test-isolation rule that a shared temp root plus `remove_dir_all(...).expect(...)` turned into intermittent false failures, and the standing model-assisted invariant (`positive_acceptance` is always false; zero findings is never a pass). It also corrects the build commands (`cargo fmt --all --check`; `cargo test --workspace` is what compiles test targets) and states plainly that clippy is advisory today because of a pre-existing pedantic-warning baseline. No code changed.
- **`identity_evidence_gap` is kept now that the endpoint gap it names is closed, and its contract text says so**: with the OpenAI accessor in place every routable provider resolves an endpoint, so the field is expected to be null today. It is deliberately not removed: it expresses the *category* "Sego cannot observe this dimension", a future provider may produce it again, and deleting it would be another contract-visible change. The schema description now states that a null value is the expectation and a non-null value names a provider without a base-URL accessor.
- **The two non-compiled CLI sketch files are now labelled as such**: `rusty-claude-cli/src/args.rs` and `src/app.rs` are not declared as modules in `main.rs` and cannot compile (`clap` is not a dependency, and `app.rs` imports a `crate::args` module that does not exist), yet they are 675 lines that read like a CLI surface — an external reviewer already described the wrong CLI by reading them. Both now open with a banner stating they are not part of the `sego` binary and that the real entry point is `main.rs`. Comment-only; nothing about the binary changes. Deleting them is left as a separate decision in case the clap-based parser is still intended as a future migration.
- **Finding-disposition vocabulary corrected in the public docs (D-3)**: `docs/AGENT_REVIEW_HANDOFF.md` and `docs/REVIEW_ARTIFACT_CONTRACT.md` recommended `confirmed` and `deferred`, which `ReviewFindingStatus::parse` rejects (`report.rs:697-711`). Both documents now list the accepted values (`open`, `acknowledged`, `fixed`, `accepted_risk`, `false_positive`, `ignored`), record the accepted alias spellings, and state explicitly that `confirmed` and `deferred` are not accepted and what to use instead. Documentation only; no code change.
- **Sidecar envelope schema realigned with the shipped output (contract change, schema-only)**: `schema/sidecar-request-response.schema.json` now describes what the sidecar actually emits. `parse_status` gained the two values the code can already produce — `parse_attempted_but_failed` (from `ReviewParseStatus`, `report.rs:504-508`) and `no_diff` (emitted by the envelope itself when the scope has no reviewable diff, `sidecar.rs:100`) — and is now declared as a top-level property, which is where the implementation puts it. `review_id` / `diff_hash` / `artifact_path` became nullable for the no-diff success case; previously `review_id: null` violated the declared `type: string`. The null companions are documented in the error envelope, and the nested `report` object is marked reserved because the implementation emits the flat `findings` + `parse_status` shape. No runtime behaviour changed. Verified by validating all six real envelope shapes (four success variants, one error, one request) against the schema with `jsonschema` Draft 2020-12.
- **Public boundary of the Python parity layer clarified**: `src/` and `tests/` are now recorded as an explicit `retained-boundary` item — a parity scaffolding (~2.1k lines) that is not the mainline, is not executed by CI, and is not part of the supported user path. The archived upstream TypeScript snapshot used for parity comparison (`archive/claude_code_ts_snapshot/`) is gitignored and has never been committed to this repository. `PARITY.md` previously stated that parity work "is not tracked publicly", which was inaccurate given the tracked `src/` tree; the corrected public/private layer table replaces it.
- The default permission mode fallback changed from `DangerFullAccess` to **ReadOnly** in code merged before v0.1.9 (PR #74), but this change was missing from the original v0.1.9 release notes. Recorded here for completeness: a plain `sego` launch now starts read-only; write/command access requires explicit `--permission-mode`, `RUSTY_CLAUDE_PERMISSION_MODE`, or project config.

## [0.1.9] - 2026-08-24

### Added
- **Sego Review Card MVP**: `sego review card`, `sego review card latest`, and `sego review card <review-id>` render an existing local review JSON artifact into an escaped, offline HTML card, update `latest-card.html`, print a compact Green/Yellow/Red summary, and request opening it in the default browser. The card is a review proof, not release approval or security certification.
- **Task acceptance record minimum practice**: adds a locale-neutral `AcceptanceRecord` contract that aggregates node, task-end, and full-review events, remediation trace, unresolved findings, and evidence links. A Chinese/English task-box and compact HTML display adapter localize Sego-owned copy while preserving original artifact evidence.
- **Development Cutover evidence docs**: documented local cutover verification, release-QA capability boundaries, public claim boundaries, and legacy source no-copy rules.
- **C21 latest review summary interface**: `sego review show latest --json` and `/review show latest --json` now print a stable machine-readable summary of the latest review proof. Human-readable `show latest` prints the latest Markdown report, and the no-review case returns a stable JSON shape or clear guidance.
- **C21 agent-callable review proof**: documented the public review artifact contract, agent handoff workflow, and integration templates so AI coding agents can call Sego after code generation and explain the resulting proof to users.
- **Reviewer identity metadata**: new review artifacts now include local trust metadata (`reviewer`, `engine_version`, `review_mode`). These fields are attribution/debug metadata, not cryptographic signatures or provenance attestations.

### Changed
- Updated review artifact JSON Schemas to include current parse/evidence status values (`parse_attempted_but_failed`, `evidence_status`) plus optional C21 metadata fields.
- Plugin lifecycle and hook script paths now use explicit synchronous platform runners instead of Windows file associations; unsupported scripts, missing interpreters, and non-zero exits fail closed.

## [0.1.8] - 2026-06-23

### Added
- **C20.6-C task-file review command execution**: when a task file explicitly tells Sego to run a review command (`Required command:`, `Required review command:`, `Must run:`, `必须执行：`, `请执行：`, `执行以下命令`), Sego now executes the allowlisted `/review staged|workspace|--full <path>` (or `sego review` equivalents) directly instead of replying conversationally. Required-marker commands that are NOT `/review`/`sego review` (e.g. `/commit`, `dotnet build`, `xcopy /E src dst`, free-form prose) are **blocked by rule** with structured `Detected / Reason / Guidance` output. Combined commands like `/cd <path> && /review staged` are blocked and the guidance preserves both the `/cd <path>` and `/review <scope>` parts so the user can run them on separate lines. Continuation lines whose lead-in negates or cautions against review (`do not run /review staged`, `skip /review staged`) are no longer interpreted as an instruction to run review.
- **C20.6-B evidence gate and recovery guidance**: review artifacts now persist an explicit evidence status alongside each finding, and the review pipeline emits structured recovery hints when intermediate artifacts are missing or stale.
- **C20.6-A review parser diagnostics and artifact export guidance**: parse-failure path now records concrete diagnostics in the JSON artifact, and the terminal output explains what the user can do next instead of silently degrading.
- **Full repository audit mode**: `sego review --full <path>` for clean cloned repos and non-Git directories. Reads key manifest files, entry points, and a context snapshot of the directory tree, then produces `.sego/reviews/` artifacts without requiring a working Git repository. This is a manifest/entrypoint/context snapshot review, not exhaustive static analysis.
- **Review parser hardening**: raw JSON findings, fenced JSON, and pretty JSON embedded in prose text are now all parsed reliably. A new `parse_attempted_but_failed` status prevents misleading "Findings 0" display when the model clearly produced findings.
- **Latest-response export improvements**: `Kind: markdown` and `Bytes` fields added to export output. Clearer recovery hint when no assistant response is available to export.

### Changed
- **Blocked task-file commands print cleanly**: direct CLI invocations like `sego "Required command: /commit"` now print a `Task command blocked` block with `Detected / Reason / Guidance` and exit zero, instead of being formatted as a parse error with an `error:` prefix and a `Run sego --help` footer.
- **Natural-language local action hardening**: conservative export boundary (requires explicit `last/previous/刚才/上一条`). Fuzzy save/export phrases without a target now route to `/dir` guidance. Safer `/dir` action directory with usage examples and safety notes.
- **Non-Git review recovery**: explains `sego review --full <path>` instead of a raw `git fatal` error message.
- **Recovery hints format**: structured `Action / Reason / Workspace / Next step` output for export and review failure modes.

### Known issues
- Review model output may still occasionally emit invalid JSON; tracked as `C20.5-REVIEW-003`.
- `sego review` (including `--full`) is a model-driven review of manifests, entry points, and a context snapshot of the directory. It is not exhaustive static analysis and is not guaranteed to find every bug.
